## 1. 这门课在讲什么（一句话）

> **当"写出代码"变得便宜，软件工程里哪些困难消失了，哪些只是换了位置？**

课程不教怎么让 AI 写代码，而是研究**当实现成本骤降时，工程的瓶颈移到了哪里**，
以及在这个前提下**什么能力还值得训练**。

**课程自己给出的答案**（讲义 §当生产变便宜，什么成为瓶颈）：
瓶颈移到"判断"——依赖**好的规格、独立检查器、测试、可观测性、清晰接口**，
目的是「**让判断也能跟上生产**」。

**课程的核心分析工具**：`Intent（意图）→ Spec（规格）→ Impl（实现）`三层之间的**缺口**。

## 2. 课程级依赖图

```
L1 欢迎来到未来 ★框架层（给出全部判据）
│   产出的判据：① 有效反馈 ② 高代价猜测 ③ 修改的局部性
│
├─► L2 提示词与上下文工程        模型看到什么、写清"完成"、注意力争夺、token 预算
│       └─► L3 版本管理 (1)      目录≠项目、快照、提交原子性、Agent 协作
│                └─► L4 版本管理 (2)  制品与可追踪性、并行复制、协作困难转移
│
├─► L5 软件工程的来龙去脉        前人的发明（流程/契约/UML）为什么存在、能力边界如何移动
│       └─► L6 需求和架构 (1)    需求泥潭、MVP 的假象、事件溯源、CQRS、DDD
│
└─► Lab1 个人数字助手（实践）
```

**读法**：L1 是**判据层**，后面每一讲都在用 L1 的判据分析新场景。
`L3 → L4` 是同一主题的上下半场，必须连着学。`L5 → L6` 同理（L5 铺垫"为什么需要需求分析"，L6 展开）。

## 3. ⭐ 跨讲概念线（本总纲最有价值的部分）

课程是**螺旋上升**的：同一个判据在多讲反复出现，每次换场景。
**按"讲次"学容易忘，按"概念线"串联才记得住。**

| 概念线 | L1 | L2 | L3 | L4 | L5 | L6 |
|---|---|---|---|---|---|---|
| **Intent/Spec/Impl 缺口** | ★提出三层 | 写清"完成"是什么 | 规格在项目里的位置 | 制品间的关系 | **契约** | 需求分析 |
| **修改的局部性**（=改动放大） | ★提出判据 | | 原子变更、提交可理解 | 变更的身份管理 | 方法与工具减少返工 | ★架构承受需求变化 |
| **反馈** | ★有效反馈判据 | 人应该盯哪些地方 | 提交是反馈点 | 协作中的反馈延迟 | **能否获得可靠反馈** | 验证与测试 |
| **上下文** | `Pr[token\|context]` | ★上下文工程 | 项目约定即上下文 | Agent 的记忆 | — | — |
| **快照与历史** | | | ★快照、撤销 | 分叉与合并 | — | ★事件溯源 |
| **成本结构变化** | ★一千倍算式 | token 预算 | 产能+1000倍 | 并行复制 | 能力边界移动 | 代码便宜后什么更重要 |

**使用方式**：学完一讲后，回到本表，问自己"**这次它在哪条线上推进了一步？**"
——这和 知识地图 里那条知识链（目的→定义→症状→成因→手段）是同一个用法。

## 4. 与已有知识的衔接（★ 决定学习顺序）

学习者刚学完 知识地图 的 **P0–P7（耦合/内聚）** 与 **A0–A37（A Philosophy of Software Design）**。
本课程与那批知识有**四处正面交汇**——从这里进入，不需要先接受任何 AI 概念：

| 交汇点 | 已有知识 | 本课程的说法 | 在哪一讲 |
|---|---|---|---|
| ① **最强** | **改动放大**（知识链 ③） | 「**修改有没有局部性：改一个地方，会不会迫使整个系统重来？**」+ 别名「焦油坑」 | **L1 §二维码 Excel** |
| ② | **接口即契约**（P0–P7） | 「工具可以组合」「**契约：调用者与实现者各自承诺什么**」 | L1 §工具组合、**L5 §契约** |
| ③ | **深模块 / 信息隐藏**（A6–A11） | 「同一规格允许许多实现」= 接口稳定、内部可换 | L1 §Intent/Spec/Impl |
| ④ | **复杂度三症状**（A1–A3） | 「制品之间的可追踪性」（traceability）——关系没维护好就成了隐性依赖 | **L4 §可追踪性** |

> ⭐ 另外：他有一条先验假设「**学 AI 必须先学软件工程和计算机基础**」。
> L1 §先用好再理解原理、L2 §AI 降低了开始学习的成本 **直接与这条假设对话**——
> 保留为**预考素材**，让他自己发现，不要直接否定（备课铁律「不直接否定学习者的先验假设」）。

## 6. 学习路径（三种，按目的选）

### 路径 A · 完整（约 12-15 次会话）

```
第 1 步  L1 §二维码 Excel + §Intent/Spec/Impl     ← 从「改动放大」进入，零 AI 前置
第 2 步  L1 §从语言模型到 Agent（S1–S8）
第 3 步  L1 其余（S9–S19）
第 4 步  L2 全部（上下文工程；接上 L1 的 context）
第 5 步  L3 全部（版本管理基线）
第 6 步  L4 全部（可追踪性；← 与 A1–A3 复杂度症状交汇）
第 7 步  L5 全部（契约；← 与 P0–P7 接口交汇）
第 8 步  L6 全部（架构；← 回到改动放大，闭环）
```

### 路径 B · 速通（3-4 次会话，只要判据）

```
L1 的 S12–S16（Intent/Spec/Impl + 局部性 + 硬编码）
L2 的「写清楚'完成'是什么」一节
L6 的「几行代码也有架构」+「让下一次需求变化有地方可去」
```

### 路径 C · 任务驱动（有一个具体项目时）

```
先做 Lab1（个人数字助手）→ 卡在哪 → 回到对应讲
```

> ⭐ **推荐路径 A，但把 L1 拆成三步**。
> 理由：学习者设定 记录他的**天然学习模式是"输出驱动"**，且自述"天然学习模式=通过系统讲授掌握知识"；
> 一次性讲完 100 分钟的内容违反 备课流程 铁律 2（单次知识输出 ≤15 行）。

### 9.1 每讲的材料清单（更新时逐个补）

| 字段 | 从哪来 |

| 转写 | `bash scripts/batch_lectures.sh <work> <BVID>` |

### 9.2 新增一讲时怎么做

1. 跑 `scripts/batch_lectures.sh` 取该讲数据
2. 取讲义：`curl https://jyywiki.cn/GSE/2026/lectN.md`，用 `extract_wiki.py` 抽正文
3. 按 备课规范 切原子点、填 11 字段 → 写 `gse-lecture-0N.lesson.md`
4. **回到本文件改三处**（只改这三处，别重写）：
   - §2 依赖图：加节点
   - §5 知识点总索引：加一行
   - §7.1 备课进度：加一行
5. 同步 知识地图：加该讲的知识点
6. **检查 §3 概念线**：新讲是否推进了某条线？是则补格子

### 9.3 已出讲次被修改时怎么做

1. 重新取讲义，与本地副本 diff
2. diff 落在哪一节 → 只重备该节的原子点
3. 在本文件 §7.1 记一行「Lx 讲义更新，重备 §yy」
4. ⚠️ 若该点已被学过（知识地图 状态为「已掌握」），**要出复习卡**，不要静默改掉
