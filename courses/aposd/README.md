## 这门教案的入口

这本书回答了一个很具体的问题（教案开头有详细说明）：

> **"把一个类拆成 8 个各司其职的小类，整体设计一定更好吗？"**

答案是**明确的"不一定"**——作者甚至给这种错误起了名字：**Classitis（类炎）**。
第 4.6 节和第 9 章就是在回答这一个问题。

**建议路径**：A0 → A5（拿到判据）→ A8 → A9 → A14–A17（拿到"什么时候别拆"）。
A6/A7/A10–A13 是中间的支撑。

## 教案面向的学习者设定

⚠️ 这份教案**不是通用的**，它面向一位 **C / 单片机 / 嵌入式背景**的学习者编写：

- **原书例子以 Java / Python 为主，本教案已改写为 C 语境**
  （模块 → `.c` + `.h`，方法 → 函数，对象 → 结构体）
- **不假设面向对象前置**
- **英文术语给中文对照**
- **类比素材限定在**：信号与系统、电机控制 / FOC、嵌入式与硬件调试、C 工程实践、通信原理

> 如果你来自不同背景：**判据与题目可以直接用，例子需要按自己的领域替换。**
