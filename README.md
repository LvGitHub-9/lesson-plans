## 这是什么

大多数"AI 总结课程"的产物是**摘要**——读起来很顺，但没法用来学。
这份教案换了个目标：**把课程变成能自我测验的材料**。

每个知识点（本仓库共 **99 个**）都按同一套 11 个字段展开：

| 字段 | 作用 |
|---|---|
| **原子性** | 只考一件事（否则拆开） |
| **材料原话** | 附章节号，能指回原文 |
| **机制 / 为什么** | 材料没给就明确写「缺口」，**不编** |
| **前置** | 依赖哪个知识点（课程几乎不声明前置，需自己推） |
| **标准范例** | 能复算 / 能复现的最小例子 |
| **常见误解** | 明确列出来 |
| **适用边界** | 什么情况下不成立 |
| **预考题** | 学**之前**问的题（先测后学优于学完再测） |
| **练习题 + 答案** | 难度递增，答案可核对 |
| **迁移题** | 换一个情境 |
| **掌握判定** | 能说清 / 能应用 / 能回忆 |

## 这份教案是怎么做出来的

它不是"把字幕喂给模型总结一遍"。核心是**先确定什么算「原话」**：

```
① 找文字源（讲义 / 课程站点）      ← 最高优先；命中就升级为「A 类材料」
② 取平台 AI 字幕（登录态）          ← 视频的「讲解」层
③ 本地 ASR + 领域术语表             ← 第二份独立转写
④ 两份转写交叉验证 → 只保留术语级分歧
⑤ 抽帧读图                        ← 只在 ① ② 都没覆盖时用
⑥ 切原子点 → 11 字段 → 教案
```

几个具体做法：

- **三层原话与可靠性分级**：讲义（★★★）> 画面（★★）> 语音转写（★）。
  **有讲义时，主溯源锚点是讲义章节号，时间戳只是辅助**——视频会被剪辑/重传，时间戳会失效。
- **两份独立 ASR 交叉验证**。实测两份转写的错误**互补**：一份系统性搞不定英文标识符
  （`main` → 慢 / 卖 / man），另一份系统性搞不定同音术语（`栈顶` → 占领）。
  两者一致的地方可以信任，分歧的地方用一帧画面就能判定。
- **崩溃修补**：实测 6 讲里有 **5 讲** whisper 出现循环崩溃（连续输出"我,我,我…"），
  **静默丢失内容**。两份 ASR 不会同时崩，所以崩溃区段用另一份补回——
  单靠一份本地 ASR 一定会静默丢东西。
- **用老师课堂上真实提的问题当预考题**。讲义里常写着「课堂提出了…」「老师在面试中问过…」——
  这些比自编的题更贴合课程设计者的教学意图（本仓库有 20+ 处这样使用）。
- **缺口如实写「缺」**。材料没给机制、没给边界、没给答案的地方，
  宁可留白也不编一个像模像样的解释。

## 阅读时请注意

- ⭐ **`【讲义原话】`** = 课程讲义明确这样表述（附章节）
- **`【视频】`** = 课堂讲述
- **`【讲义原话·课堂提问】`** = 老师在课堂上真实提出的问题
- **`【外部补充】`** = 教案作者补的，**不是讲义原有**
- **`【待查证】`** = 无法确证（讲义里引用了大量外部文献，教案作者未逐条核对原文）

每讲末尾都有**缺口汇总**——把"材料没说清的地方"显式列出来，而不是填满字段。

## 教案面向的学习者设定

这份教案不是通用的：它**面向一位 C / 单片机 / 嵌入式背景的学习者**编写，
并据此做了大量改写。这一点是教案的方法论核心，所以保留在文件里：

- **不假设面向对象前置**——契约等 OO 概念已改写为 C 的函数与结构体
- **未学过的领域概念一律展开**——操作系统 / 网络 / 数据库 / 编译原理的术语逐项展开
- **英文术语给中文对照**
- **类比素材限定在**：信号与系统、电机控制 / FOC、嵌入式与硬件调试、C 工程实践、通信原理
- **避免使用的类比**：数据结构、AI / 机器学习、大型软件架构与设计模式

> 如果你来自不同背景，这些「改写」正好展示了**同一份材料如何适配不同读者**——
> 直接可用的部分是那些判据和题目；例子需要按你自己的领域替换。
